# Creature Handbooks launch site

User request: launch an attractive, fast website inspired by the existing Deerfield handbook cover, host on GitHub Pages, offer the complete book as a sample, and let visitors request a custom handbook for their own city.

Build a small static HTML/CSS/JavaScript site in `dist/`. Use the actual illustrated cover and real sample pages; royal/navy blue, sunny yellow, green, warm cream, strong playful typography and clean editorial composition. Responsive phone layout, accessible controls and restrained motion. No external fonts or runtime dependencies needed.

Brand working name: Creature Handbooks. Lead proposition: a city's real nearby creatures presented as characterful handbook entries, including animals, insects, plants, trees and fungi. City plus state/country are the required location; neighborhood or ZIP is optional. Never invent species lists for new cities, testimonials, pricing, deadlines, print fulfillment, automatic generation or completed-order claims.

Sample: the finished, complete 19-page `Creatures of Deerfield, IL.pdf`, 7,756,574 bytes, SHA256 `10227b544f106f54419b1cd9d20d1fbbabf583996a4f7b6d6c19100bb4552bdc`. Public sample copies are authorized. Include direct PDF view/download and a mobile-friendly gallery using real rendered sample pages. Show actual creature profiles, gear and local-place pages.

Request flow: city, state/region/country, optional neighborhood/ZIP, reply email, optional notes. A clear review step builds a request; visitors explicitly open an email draft in their own mail app or copy the text. No false submitted state. An actual receiving address must be configured before email handoff is enabled; user approval to expose the current inbox is pending. Do not publish a personal email without that approval. No payment collection or pricing claims: this initial project showcase collects interest in a custom city edition, with details discussed by reply.

Target hosting is GitHub Pages, not Sites hosting. Use repository-relative asset paths so a project subpath works. Minimal Pages deployment workflow serves `dist`, with `.nojekyll`. Keep source, sample assets and docs only; no credentials, original book-production internals or customer data. No tracking.

Acceptance: actual sample hashes match; relative assets load under a project prefix; desktop and phone layouts have no overflow; gallery keyboard controls and form validation work; adversarial native agent review passes; public GitHub Pages URL serves the completed site and sample PDF. Verify without sending a real customer request. User has authorized deployment and publishing the sample.
